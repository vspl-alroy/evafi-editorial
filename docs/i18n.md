# Translations

Write articles in English only: `content/<slug>.md`. Spanish lives at `content/es/<slug>.md` and is served at `/es/<slug>/`.

## Flow
1. English article merged to `main` → the **Draft translations** workflow runs `scripts/translate.ts`, which asks Claude for a Spanish draft and opens a PR.
2. Reviewer edits the Spanish in the PR, then changes the first line `status=draft` → `status=reviewed`.
3. The **Translation review** check passes only when no draft is left. Merge → deploy.

## Rules
- **AI never overwrites a reviewed or hand-written translation.** Only files marked `status=draft` can be regenerated (`--force <slug>`).
- Drafts are never published: the production build skips them (set `INCLUDE_DRAFTS=1` to preview locally).
- If the English article changes later, `npx tsx scripts/translate.ts --check` prints `STALE`. A human updates the Spanish, then runs `--fix-hash <slug>`.
- An article with no translation is simply absent from `/es/`.
- Keep `{State}`, image paths, numbers and the structure (headings, bullets, numbered steps) identical; the script validates this.
- UI text (footer, buttons) is in `src/i18n.ts`. Terminology is in `content/i18n/glossary.<locale>.json`.

## Setup (once)
- Repo secret `ANTHROPIC_API_KEY`.
- Settings → Actions → General → "Allow GitHub Actions to create and approve pull requests".
- Settings → Branches → require the `Translation review / check` status check on `main`.
- Set `GATSBY_SITE_URL` (build env) to the real domain so hreflang URLs are right.

## New language
Add the code to `locales` and a block to `ui` in `src/i18n.ts`, add `content/i18n/glossary.<code>.json`, then run `npx tsx scripts/translate.ts --locale <code>`.
